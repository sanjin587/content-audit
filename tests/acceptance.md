# v2.0 人工验收清单

本清单验证可观察行为，不以固定措辞为通过标准。

## 1. 旧能力不回退

- 输入“先审计，不要改”，输出没有完整重写稿。
- 输入 A/B 两版，输出明确选择一个版本或明确组合方案，不说“各有优点”后结束。
- 输入发布数据，输出区分观察与推断，并只给一个下一轮主要变量。
- 抖音、X、公众号请求分别使用对应平台判断。

## 2. 选题与内容评分分离

- 只有选题时使用八维 80 分。
- 已有成稿审计时使用六维 60 分。
- 需要两种评分时分别展示，不出现 140 分总分或混合平均分。

## 3. 事实和作者声音

- 改写前出现 `protected_elements`。
- 数字、时间、说话人和案例归属与输入一致。
- 原文含混的主语、代词、对象或因果关系被列入 `unresolved_ambiguity`；未确认前沿用原表述，不补主语。例如“没觉得多厉害”不能改成“没觉得自己多厉害”。
- 缺少证据时明确说明，不补造数据、用户反馈或平台机制。
- 改写没有无依据的励志升华，也没有把真人口语全部整理成整齐排比。

## 4. 改写控制

- 轻改保留大部分原文。
- 重构仍保留所有受保护事实。
- 口喷版可以自然说出口，但不会让每句话都像标题。
- 输出显示实质修改的前后对照，并提供完整稿件和二次检查。

## 5. 固定审计输出

审计必须包含：一句话结论、六维评分、最大掉人点、最可能掉人的一句、保留 3 处、删改 3 处、只能改一处时的优先项。

## 6. 结构化协议

- `examples/sample_input.json` 是有效 JSON，并符合输入 Schema。
- `examples/sample_output.json` 是有效 JSON，并符合输出 Schema。
- 普通对话不被强制包装为 JSON。

## 7. 真实素材回归

至少人工检查 5 条三金旧稿和 5 条热点素材。若输出更像新闻、更整齐或更像通用 AI 文，优先调整 Skill 规则，不以增加 UI 功能掩盖问题。

## 8. 范围边界

本版本不执行自动发布、自动剪辑、自动抓热点、登录账户或生产数据库修改。任何发布效果都需要真实数据验证。
